INTRODUCTION                                                      *cvs-intro*

cvs.nvim is a Neovim-native CVS workflow plugin.

The main status and file-diff workflows follow the corresponding Fugitive
commands while keeping CVS semantics.

==============================================================================
COMMANDS                                                        *cvs-commands*

                                                          *:Cvs*
:Cvs[!] [path]
        Open the themed CVS status view. Like Fugitive's :Git summary, it
        uses a horizontal split by default. Standard Ex layout modifiers
        override that layout for one invocation:
>
            :vertical Cvs
            :aboveleft vertical Cvs
            :belowright Cvs
            :tab Cvs
<
        |:CvsStatus| supports the same modifiers. To make a vertical status
        view the default, set ui.status.kind to "vsplit" (see |cvs-config|).
        The plugin does not reserve a global <Leader> mapping.
        While focused in an existing status split, Neovim's built-in
        |CTRL-W_H| and |CTRL-W_J| commands move it to a left vertical or bottom
        horizontal layout respectively.

        Move to a file and press <CR> to open it in the original editing window.
        Use o to open it in a split matching the status layout: horizontal for
        a horizontal status window and vertical for a vertical status window.
        Use gO, O, or p to open it in a vertical split, tab, or preview.
        Press dd for a full side-by-side diff against the
        checked-out revision,
        or = on a modified, added, or unknown file to toggle unified hunks
        inline. Inline diffs also show source-language syntax colors when a
        Tree-sitter parser is installed, without replacing diff backgrounds.
        Press gl on a tracked file to open its revision history.
        Added and unknown files are shown as entirely new content
        against an empty base. Press - on a file,
        visual range, or section heading to toggle the commit selection. Press
        a on an unknown or removed file, visual range, or section heading to
        add or restore the eligible files. Press A on an unknown file, visual
        range, or the Unknown heading to add files in binary mode with -kb.
        Press cc to open a commit message buffer immediately for the selected
        files. CVS validates the selected files when the commit runs. The status
        view refreshes after the commit completes, and CVS errors remain visible
        in the commit buffer.

        Tracked files deleted from the working copy appear in the Missing
        section. Press r on a missing file to schedule its removal in CVS; it
        then becomes selectable for commit in the Removed section.

        Press X on a file, section heading, or visual range to discard those
        changes after confirmation. Modified and conflicted files are restored
        with cvs update -C, missing files are restored with cvs update, and
        scheduled removals are cancelled with cvs add. Unknown and newly added
        files are permanently deleted; the confirmation identifies this case.
        CVS .# recovery files are grouped in a dedicated CVS Backups section.
        Move to that section heading and press X to delete every listed backup
        after one confirmation. Backup files cannot be added to CVS with a or
        A.
        CVS creates .# backup files while reverting modifications with update
        -C. Backups newly created by X are removed after a successful revert;
        pre-existing .# files are left untouched.

        Status queries run asynchronously. The buffer opens immediately with
        a loading message, and refreshes keep the previous snapshot visible
        while CVS runs. Refreshes preserve the file under the cursor when it
        remains in the result. A recent cached snapshot is reused when
        possible. Cached snapshots expire after five minutes and are discarded
        when a working-copy buffer is written. Use [!] or press R in the status
        view to query CVS again immediately.

        Press q to hide the status view. Its selections, inline diffs, and cursor
        position are retained for the current Neovim session. Running |:Cvs|
        again in the same workspace and scope reopens that state; |:Cvs| with
        [!] also refreshes it against CVS.

                                                         *:CvsStatus*
:CvsStatus[!] [path]
        Alias for the CVS status view used by |:Cvs|.

                                                        *:CvsUpdate*
:CvsUpdate [path]
        Update the working copy, including repository directories that are
        missing locally, and open the update result view.

                                                         *:CvsAdd*
:CvsAdd [path]
        Add the current buffer or the provided path to CVS.

                                                         *:CvsRemove*
:CvsRemove [path]
        Schedule the current buffer or the provided path for CVS removal.

                                                         *:CvsCommit*
:CvsCommit [path]
        Open a direct CVS commit message buffer for the current workspace or
        path.

                                                         *:CvsDiff*
:CvsDiff[!] [path]
        Without [!], open the original full side-by-side diff against the
        checked-out CVS revision. The working buffer remains editable and
        includes unsaved changes. With [!], stream a unified CVS diff and show
        only changed hunks with surrounding context. Streamed hunks are
        reconstructed into read-only CVS BASE and CVS WORKING panes using native
        diff highlighting, synchronized scrolling, and synchronized cursors.
        The streamed view uses the configured diff window kind, which defaults
        to a tab. Paired streamed views support tab and vsplit; other configured
        kinds fall back to a tab. Use ]c and [c to move between changes.
        Streamed diffs compare the file on disk, so unsaved buffer changes are
        not included.

                                                        *:Cdiffsplit*
:Cdiffsplit[!]
        Without [!], open the original full side-by-side diff in a vertical
        split. The working buffer remains editable, including unsaved changes,
        and the CVS base buffer is read-only. With [!], open streamed unified
        diff hunks as synchronized, read-only CVS BASE and CVS WORKING panes in
        a vertical split. Closing either pane restores the original working
        buffer. CVS compares the file on disk for the streamed form, so unsaved
        changes are not included and are called out in the view.

                                                        *:CvsLog*
:CvsLog[!] [path]
        Open CVS history for the current context or explicit path. In a normal
        file buffer, omitting [path] retains the file-history workflow. In a
        directory buffer it opens history for that directory subtree; opening
        the workspace root shows the whole project. An explicit file or
        directory always selects that scope:
>
            :CvsLog %
            :CvsLog src/module/
            :CvsLog .
<
        Use :CvsLog! to open history for the complete detected workspace scope
        regardless of the currently focused file or directory. This is the
        fastest route to a recent project commit when its ID is not already
        known.

        CVS-backed status buffers resolve to their configured scope or workspace.
        From |:Cvs|,
        gl continues to open history for the tracked file under the cursor.

        File history shows each revision's date, author, state, line counts,
        tags, commit message, and shared CVS commit ID when the server provides
        one. Press = to toggle its highlighted predecessor diff inline, and
        <CR> or d for the full diff. On the first branch revision, the
        predecessor is the branch point; the initial trunk revision is shown
        as additions against an empty file.

        Directory history uses `cvs rlog` so removed repository files are not
        omitted. File revisions are grouped and sorted by their exact shared
        commit ID. Press = on a commit to expand or collapse its affected
        files, then d on a file for its revision diff. Revisions without a
        commit ID remain separate rather than being guessed from timestamps or
        messages. To avoid downloading the entire repository history, directory
        logs ask the server for the last 30 days by default, omit symbolic-name
        lists, suppress files with no matching revisions, and render at most 200
        grouped commits. The active bounds are shown at the top of the buffer.
        Press L to double both bounds and query an older range. File-local logs
        remain unlimited.

        In either form, yc copies the selected shared commit ID into the
        unnamed register and cr opens a complete revert plan for it. Press R
        to refresh or q to close. Like |:Cvs|, the log opens in a half-height
        horizontal split by default. Use :vertical CvsLog,
        :belowright CvsLog, or :tab CvsLog to override the layout. Configure
        ui.log.kind, ui.log.height, or ui.log.width to change its default.

                                                     *:CvsRevert*
:CvsRevert {commit-id}
        Discover every repository revision carrying the exact shared commit
        ID and open a revert plan. This is also available as cr on an entry in
        |:CvsLog|. The lookup covers the workspace repository module, including
        removed files, and never infers changeset membership from dates or log
        messages.

        Before enabling the revert, the plan verifies that every affected
        directory is checked out, affected buffers have no unsaved changes,
        and CVS reports no local or incoming changes for the affected files.
        Press d on a file to inspect its reverse diff. Press R to apply the
        plan to the working copy, or cc to apply it and then open a prefilled
        commit message. The final remote commit is still explicit: submit the
        commit buffer with :write or CTRL-C CTRL-C.

        Modified files are reversed with native CVS merges of the form
        `cvs update -j BAD -j PREDECESSOR`, preserving later revisions where
        CVS can merge them. Files introduced by the commit are scheduled for
        removal, and files removed by it are restored from their predecessor.
        A merge conflict or command failure stops the operation before a commit
        is opened. Earlier files may already be locally modified if a later
        file fails; the plan reports this and leaves the changes for review.

                                                        *:CvsAnnotate*
:CvsAnnotate [path]
        Open the scaffolded annotate workflow.

                                                        *:CvsConflicts*
:CvsConflicts [path]
        Open the scaffolded conflict workflow.

CONFIGURATION                                                      *cvs-config*

Status snapshots are cached for five minutes by default. The cache can be
configured through setup():
>
    require("cvs").setup({
      cvs = {
        timeout_ms = 60000,
      },
      status = {
        cache = {
          enabled = true,
          ttl_ms = 300000,
        },
      },
      diff = {
        max_bytes = 16777216,
        max_lines = 100000,
        syntax_highlighting = true,
        preserve_syntax_colors = true,
      },
      log = {
        repository = {
          days = 30,
          max_commits = 200,
        },
      },
      ui = {
        status = {
          kind = "vsplit",
          width = 0.5,
        },
      },
    })
<
Directory-scoped |:CvsLog| queries are limited to the last 30 days and 200
commits by default. Set log.repository.days or log.repository.max_commits to a
different positive number; 0 disables that bound. The day limit is applied by
`cvs rlog -d` on the server and therefore provides the main performance gain.
The commit limit additionally bounds rendering and retained parsed data. Press
L in a directory log to double the current limits for that buffer.

The inline |:CvsLog| revision diff is limited to 200 diff lines by default.
Set ui.log.preview_lines to another positive number, or 0 for no line limit.
The <CR> full-diff view is unaffected by this setting (but uses the general
|:CvsDiff| output limits). With a Tree-sitter parser and highlight query for
its source filetype, both the log and status inline diffs overlay
source-language foreground colors on old and new lines while preserving diff
backgrounds. Highlighting runs only for the opened diff, after it loads, and
is bounded to the first
1000 diff lines, 256 KiB, 32 hunks, and 8000 captures. Remaining lines, or
files without an available parser, retain regular diff colors. Set
diff.syntax_highlighting to false to disable source colors in these views.

CVS commands time out after 60000 milliseconds by default. Increase
cvs.timeout_ms for remote or large repositories whose commands take longer.
The status kind accepts "split", "vsplit", "tab", or "floating". height sizes
horizontal status splits and width sizes vertical status splits; values below
1 are proportions of the source window.

Set enabled to false to always query CVS. A ttl_ms value of 0 also prevents
cache reuse. Regardless of these settings, the [!] form of |:Cvs| and R in the
status view force an immediate refresh.

For |:CvsDiff| and |:Cdiffsplit| with [!], and for tracked status inline diffs,
output is streamed and only unified hunks are retained. Added and unknown status
files are read locally to generate their empty-base diff. max_bytes bounds raw
streamed output or new-file content, and max_lines bounds retained hunk and
diagnostic lines. Reaching either limit leaves the collected hunks visible and
adds a truncation notice instead of buffering the remaining output. Set either
value to 0 to disable that limit. Plain full diffs still load both complete
files and are not covered by these limits.

Diff panes use their source filetype and start Tree-sitter highlighting when a
parser is available. If no parser is installed, they fall back to Vim syntax
highlighting. preserve_syntax_colors maps the standard diff groups to
background-only CVS groups inside diff windows, allowing language foreground
colors to remain visible. Set either syntax_highlighting or
preserve_syntax_colors to false to disable that behavior.
